# HAN-26 — страница «Бюджеты» и переключатель активного бюджета в шапке

Linear: [HAN-26](https://linear.app/hangelify/issue/HAN-26) · эпик HAN-21 · сервер: HAN-22 (готово, server dev
899cca6), [HAN-146](https://linear.app/hangelify/issue/HAN-146) (роль в списке, блокирует) · дальше: HAN-27 (перенос
чеков) использует ссылки `?hid=` из этой задачи.
Размер: проект (~3 пункта): новая страница, переключатель, ссылки с `hid`, переименование в UI.

## Зачем

Сервер уже умеет несколько бюджетов (household), а фронт — нет: бюджет выбирается только в окне нового чека,
создать или удалить его нельзя, и не видно, в каком бюджете ты сейчас. Пользователь заводит «Семья», «Отпуск»,
«Ремонт», переключается между ними из шапки и всегда видит активный.

## Что уже есть

- `HouseholdContext`: список (`['households']`), активный бюджет в `localStorage` (`pickActiveHousehold` —
  запомненный или первый), `setActiveHouseholdId`, обработка 403 «доступ потерян», статусы
  `idle | loading | ready | empty | error`.
- **Ключи react-query** всех household-запросов уже `['households', hid, …]` (чеки, черновики, failed, дубликаты,
  деталь, картинка, дашборд, категории, подкатегории, магазины); списки держат `placeholderData` только при том же
  `hid`. Переключение не покажет данные старого бюджета — нужна только проверка тестом.
- `billDraftStore` и `billBatchStore` хранят `hid`; экран проверки черновика (`NewBillReview`) уже пишет «этот
  черновик из бюджета X, переключитесь». Колокольчик загрузок показывает пачки всех бюджетов, ссылка «Review» ведёт
  на `/bills/drafts/:id` без `hid`.
- `/households/settings` (`HouseholdSettings`): имя и валюта активного бюджета; участнику — только чтение (по
  `role === 'member'` или 403 после сохранения).
- Сервер (HAN-22): `POST /households {name, currency?}`; `GET /households` — `name` (своё имя или основное),
  `original_name`, `currency`, `created_at`, `member_count`, `bill_count`, сортировка по `created_at`;
  `PUT /households/:hid {name?, currency?}` — owner; `PUT /households/:hid/me {display_name: string | null}` —
  любой участник; `DELETE /households/:hid` — owner, 204. Ошибки 409 с `reason`: `household_limit` (5 бюджетов,
  свои + приглашённые), `last_household`, `household_has_members`.
- Роли в списке нет — добавляет HAN-146 (`role: 'owner' | 'member'`).
- Локаль только `en`; русской нет.

## Решения владельца (2026-11-16/17)

1. Одна страница «Бюджеты» вместо `/households/settings`; старый адрес — редирект.
2. Переключатель — отдельная кнопка в шапке; на мобильном только иконка, название активного — в боковом меню.
3. Ссылка на чек несёт бюджет: `/bills/…/:id?hid=…`; при несовпадении с активным — автопереключение и уведомление.
4. Роль в списке добавляет сервер (HAN-146), фронт её не вычисляет.

## Цели / не цели / анти-цели

**Цели:** видеть все свои бюджеты и активный; создать, переименовать, сменить валюту, удалить (owner); своё имя
бюджета (любой участник); переключение из шапки в один клик; ссылка на чек открывает его в нужном бюджете;
в интерфейсе «Budget» вместо «Household».

**Не цели:** приглашения и участники (UI); перенос чеков (HAN-27); русская локаль (только `en`-строки);
`hid` в путях всех страниц; восстановление удалённого бюджета; выбор направлений категорий при создании (HAN-60).

**Анти-цели:** после переключения видны данные прошлого бюджета; участнику показаны кнопки, которые сервер
отклонит; пользователь остаётся на странице чека, которого нет в активном бюджете («не найден» после
переключения); ссылка `?hid=` возвращает старый бюджет после ручного переключения.

## Подходы

**Страница.** (выбрано) Одна страница-список с правкой в карточке — всё о бюджетах в одном месте, правка
неактивного без переключения. Отвергнуто: оставить `/households/settings` для активного + список отдельно — два
похожих экрана.

**Переключатель.** (выбрано) Кнопка-выпадашка в шапке с названием активного. Отвергнуто: подменю в UserMenu —
два клика и не видно активного бюджета.

**Ссылки на чек из другого бюджета.** (выбрано) `?hid=` в ссылке и автопереключение — без новых запросов, готово
для HAN-27. Отвергнуто: перебор бюджетов при 404 (до 5 запросов, «не найден» = 5 запросов); ничего не делать.

**Роль.** (выбрано) Поле `role` в списке с сервера (HAN-146). Отвергнуто: N запросов карточек; «owner, пока не
403» — нарушает «участник видит только чтение».

## Дизайн

### Терминология и i18n

- В UI «Budget» / «Budgets» вместо «Household» во всех `en`-строках (`households.json`, `header.json`,
  `bills.json`: `newBillModal.household`, `noHousehold`, `review.otherHousehold*`, `dashboard.json` при упоминании).
  Ключи i18n и код (`household`, `hid`) не переименовываем.
- Новые строки — в namespace `households`.

### API и хуки (`src/api/households.ts`, `src/hooks/`)

- `householdsApi`: `create({name, currency})`, `update` (есть), `updateMine(hid, {display_name})`, `remove(hid)`.
  Сортировку на клиенте в `list` убрать — сервер сортирует (`created_at`, `id`); оставить порядок ответа.
- Тип `Household`: `original_name`, `bill_count`, `role: 'owner' | 'member'` (обязательное после HAN-146).
  Ответы мутаций (`POST`, `PUT`) — `HouseholdResponseDto` без `bill_count` (и без `role`, если HAN-146 добавит
  его только в список): тип `HouseholdResponse`; в кеш списка мутации **не пишут ответ поверх**, а сливают
  изменённые поля в существующую строку или инвалидируют `['households']`.
- Хуки: `useCreateHousehold`, `useUpdateHousehold` (есть, поправить слияние), `useUpdateMyHouseholdName`,
  `useDeleteHousehold`. Все — `meta: OWN_FORBIDDEN_META` (403 обрабатывается на месте, без «доступ потерян»).
- Создание: после успеха **дописать новую строку в кеш списка** (`bill_count: 0`, `role: 'owner'`) и затем
  инвалидировать список — иначе `setActiveHouseholdId` молча игнорирует id, которого ещё нет в кеше. **Новый
  бюджет не делать активным** автоматически — пользователь остаётся там, где был; в уведомлении кнопка «Switch
  to it». (Решение исполнителя-дизайнера: создание на странице списка — переключение без спроса неожиданно.)
- Существующий баг: `useUpdateHousehold` пишет ответ `PUT` целиком поверх строки списка и теряет `bill_count`
  (и `role`) — исправить слиянием полей.
- Удаление: после 204 убрать строку из кеша, `removeQueries(['households', hid])`; если удалён активный —
  контекст сам выберет первый оставшийся (`pickActiveHousehold`), уведомление «Budget deleted».
- Смена валюты: как сейчас — инвалидировать `['households', hid]` (суммы пересчитываются).

### Страница «Бюджеты» (`/households`, `src/pages/households/HouseholdsPage.tsx`)

- Маршрут `/households`; `/households/settings` → `<Navigate to="/households" replace />`. Пункт меню
  пользователя «Budgets» ведёт сюда. `HouseholdSettings` удаляется, его форма переезжает в карточку.
- Шапка страницы: заголовок «Budgets», кнопка «New budget». При 5 бюджетах кнопка неактивна, подсказка
  «You can have up to 5 budgets» (лимит — константа фронта = серверному дефолту; 409 `household_limit` всё равно
  обрабатывается текстом).
- Окно создания (`Dialog`): имя (обязательно, ≤ 255, трим) и валюта (`CurrencySelect`, по умолчанию валюта
  активного бюджета — решение исполнителя; у пользователя на фронте валюты нет). Ошибки: 409 `household_limit` —
  текст в окне; прочие — тост.
- Список карточек в порядке сервера. Карточка (свёрнутая): имя, основное имя мелко, если отличается
  (`original_name !== name`), валюта, роль (бейдж «Owner»/«Member»), «N bills», метка «Active». Кнопки:
  «Make active» (если не активный), «Edit» (раскрывает форму в карточке).
- Форма в карточке:
  - **Owner:** имя (основное, `PUT :hid {name}`), валюта (с подсказкой о пересчёте, как сейчас), «Save»
    отправляет только изменённые поля (`changedFields`). Отдельно — «Delete budget».
  - **Member:** имя и валюта только на чтение + поле «Your name for this budget» (`PUT :hid/me`), кнопка «Reset»
    → `display_name: null`, пустая строка — ошибка валидации. Подсказка «Only the owner can change name and
    currency».
  - Поле «Your name for this budget» с «Reset» показывается **всем**, включая owner: сервер разрешает
    `PUT :hid/me` любому участнику, и у owner `name` может отличаться от основного. Поле основного имени у owner
    заполняется из `original_name`, не из `name`. (Решение исполнителя-дизайнера после проверки спеки.)
- Удаление (`ConfirmDialog`, destructive): «Delete “{name}”? It has {count} bills. This can't be undone.»
  (при 0 — без фразы про чеки). Кнопка неактивна с подсказкой, если `households.length === 1` («You can't
  delete your only budget») или `member_count > 1` («Remove other members first»). 409 от сервера: тексты для
  `last_household`, `household_has_members`; 403 — «Only the owner can delete».
- Пустые/ошибочные состояния: `loading` — `LoadingFallback`; `error` — «Could not load your budgets» + «Try
  again» (как сейчас). `empty` (сервер не допускает, но статус есть) — текст «You have no budgets» и кнопка
  создания.

### Переключатель в шапке (`src/components/header/HouseholdSwitcher.tsx`)

- `DropdownMenu`: триггер — иконка (`Wallet`) + имя активного (обрезка `max-w-[10rem]`) + шеврон; на мобильном
  (`md:hidden`) только иконка с `aria-label="Budget: {name}"`.
- Содержимое: заголовок «Budgets», радио-список бюджетов (`DropdownMenuRadioGroup`, имя + валюта мелко),
  разделитель, «Manage budgets» → `/households`.
- Показывается при `status === 'ready'`, в том числе при одном бюджете (видно, где ты; путь к созданию).
- Место: справа в шапке перед колокольчиком. Мобильное боковое меню (`MobileNav`) получает строку «Budget:
  {name}» над навигацией (ссылка на `/households`).
- Выбор бюджета: `setActiveHouseholdId(id)`; если текущий маршрут — карточка чека (`/bills/:id`,
  `/bills/confirmed/:id`, `/bills/drafts/:id`), перейти на родительский список (`navigate('..')` по пути, без
  `hid` в query, сохранив прочие фильтры). Остальные страницы остаются на месте и перезапрашивают данные по
  новому `hid`.
- `HouseholdSelect` в окне нового чека остаётся (меняет активный бюджет, как сейчас).

### Ссылки на чек с `hid`

- Хелпер `billPath(section, id, hid)` → `/bills[/confirmed|/drafts]/:id?hid=…`. Используется там, где бюджет
  может отличаться от активного: колокольчик загрузок (`BatchItemRow` — `hid` пачки), `NewBillReview` после
  сохранения (`savedHid`), `FailedBillCard`, `DuplicatePairCard`, `DuplicateOfBadge` и навигация списков —
  тоже с `hid` (единообразно; ссылки внутри списка всегда в активном бюджете, но ссылку можно скопировать).
- `BillDetailRoute` читает `hid` из query:
  - совпадает с активным или отсутствует — как сейчас;
  - есть в списке бюджетов и не активный — `setActiveHouseholdId(hid)` и тост «Switched to budget {name}»;
  - не найден в списке — один `refetch()` списка (список мог устареть: бюджет создан в другой вкладке, только
    что принято приглашение); нашёлся — переключить как выше; нет и после refetch (нет доступа, бюджет удалён) —
    «This bill is in a budget you can't access» вместо запроса чека.
  - После применения `hid` убирается из адреса (`replace`), чтобы ручное переключение не возвращало бюджет
    ссылки, а «назад» не переключал снова.
  - Пока список бюджетов грузится — ждать (`status !== 'ready'` → загрузка).
- `NewBillReview` («черновик из бюджета X»): добавить кнопку «Switch to {name}» рядом с текстом.

### Тесты

- `HouseholdSwitcher`: показывает активный; выбор вызывает `setActiveHouseholdId` и пишет `localStorage`; на
  карточке чека переход на список; «Manage budgets» ведёт на `/households`.
- Переключение: после смены бюджета `useConfirmedBills` / дашборд запрашивают новый `hid` и не показывают строки
  старого (MSW, интеграционный тест на одной странице).
- `HouseholdsPage`: список с ролью, валютой, числом чеков, активным; создание (успех, 409 лимит, кнопка
  неактивна при 5); правка owner (только изменённые поля); member — только чтение + своё имя, сброс; удаление —
  подтверждение с числом чеков, неактивно для единственного / с участниками, 409 тексты, удаление активного
  выбирает другой.
- `BillDetailRoute` с `?hid=`: переключает и убирает параметр; недоступный `hid`; совпадающий — без изменений.
- Редирект `/households/settings` → `/households`.
- Снимки строк: в `en`-локали не осталось «Household» в видимых текстах (кроме ключей).

## Зависимости и порядок

1. HAN-146 (сервер, `role` в списке) — до мержа фронта; фронт можно писать параллельно на моках.
