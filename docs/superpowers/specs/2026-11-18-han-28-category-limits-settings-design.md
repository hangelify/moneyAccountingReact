# HAN-28 — Настройка лимитов по категориям (фронт)

Linear: [HAN-28](https://linear.app/hangelify/issue/HAN-28) · эпик HAN-21 · сервер HAN-24 (Done,
спека `accounting_node/accounting/docs/superpowers/specs/2026-11-15-han-24-category-limits-design.md`),
отчёт HAN-25 (Done, `…/2026-11-17-han-25-limits-report-design.md`) · следующий фронт HAN-29.
Дата: 2026-11-18 · Статус: одобрено владельцем 2026-11-18.
Размер: небольшой проект (новый маршрут, API-клиент и хуки, строка с инлайн-формой, диалог снятия).

## Зачем

Пользователь хочет поставить себе цель «на Еду не больше 400 € в месяц» и потом (HAN-29) видеть,
уложился ли он. Эта задача — место, где лимиты задают: список категорий бюджета, у каждой — лимит
(сумма + период) или «без лимита»; поставить, изменить, снять. Лимиты обычно настраивают пачкой,
один раз, поэтому ввод должен быть быстрым. Главная тонкость — изменение лимита пишется с начала
текущего периода, иногда задним числом, и пользователь должен это видеть **до** сохранения.

## Цели

- Страница `/households/:id/limits` для любого бюджета пользователя (не только активного).
- Поставить / изменить / снять лимит категории верхнего уровня, период из 4 значений, валюта бюджета.
- До сохранения видно, с какого периода действует новый лимит («с ноября 2026»), и что прошлые
  периоды не меняются; при смене типа периода — какие периоды останутся без лимита.
- Ошибки сервера (409, 404, 400) показаны понятным текстом.

## Не цели

- История версий лимита — HAN-147.
- Отчёт исполнения — HAN-29; перенос остатка и «не переносить» — HAN-148.
- Управление категориями (создание, переименование) — HAN-61.
- Лимиты на подкатегории, общий лимит бюджета.

## Анти-цели

- Пользователь меняет период и не понимает, что лимит переписался с начала квартала/года.
- Подсказка «действует с …» расходится с тем, что реально записал сервер.
- Молча потерянная правка (409/404 без объяснения).

## Решения владельца (2026-11-18)

1. **Где живёт экран — на странице бюджетов**, отдельная страница бюджета `/households/:id/limits`;
   на `HouseholdCard` — кнопка «Лимиты». (Отвергнуты: отдельный `/limits`, общий экран с HAN-29,
   блок внутри раскрытого редактора карточки.)
2. **Правка — инлайн в строке** с подсказкой под ней (отвергнута модалка на каждую категорию).
3. **Истории версий нет** — вынесена в HAN-147.
4. Подход к данным — как в проекте (React Query + react-hook-form + zod), без оптимистичных обновлений.

## Что уже есть

- **Сервер (dev).** `households/:hid/category-limits`, `JwtAuthGuard + HouseholdMemberGuard`,
  **любой участник** может менять лимиты (HAN-24) — режима «только просмотр» нет.

  | Метод | Путь | Тело | Ответ | Ошибки |
  |---|---|---|---|---|
  | `GET` | `/category-limits` | — | `CategoryLimitDto[]` — действующие сегодня (открытые и доживающие), по одной на категорию | — |
  | `POST` | `/category-limits` | `{category_id, period_type, amount}` | 201 `CategoryLimitDto` | 404 категория не в бюджете/удалена; 409 уже есть открытый лимит; 400 |
  | `PUT` | `/category-limits/:categoryId` | `{period_type, amount}` | 200 `CategoryLimitDto` | 404 нет открытого лимита (в т. ч. доживающий) |
  | `DELETE` | `/category-limits/:categoryId` | — | 200 `CategoryLimitDto` с `effective_to` | 404 нет открытого лимита |

  `CategoryLimitDto = { id, category_id, category_name, category_archived, period_type, amount,
  currency, effective_from, effective_to }`, даты `YYYY-MM-DD`, `effective_to` — первый день **без**
  лимита (half-open), `null` у открытого. `period_type`: `MONTHLY | QUARTERLY | SEMI_ANNUAL | YEARLY`.
  `amount > 0`, `≤ 1e12`, не больше 2 знаков. Валюта в запросе не передаётся — сервер берёт валюту
  бюджета.
- **Правила сервера, которые видны в UI.**
  - Установка (`POST`/`PUT`) пишется с `S = limitPeriodStart(newType, todayUTC)`; версии после `S`
    переписываются. Месяц → квартал 18 ноября ⇒ квартал с 1 октября, октябрь и ноябрь *как месяцы*
    остаются без лимита.
  - Снятие (`DELETE`): лимит доживает до `limitPeriodEnd(type, todayUTC)` и ставит отметку «не
    переносить» на текущий период (HAN-25). Повторный `POST` в том же периоде снимает отметку.
  - `PUT` с тем же значением идемпотентен.
  - Календарные границы: кварталы с янв/апр/июл/окт, полугодия с янв/июл.
- **Фронт.**
  - `src/api/categories.ts` — `categoriesApi.list(hid)` (сервер не отдаёт удалённые категории);
    кэш `['households', hid, 'categories']`, `staleTime` 5 мин (`useCategoryTree`).
  - `HouseholdsPage` → `HouseholdCard` (кнопки «Сделать активным», «Изменить»), `useHouseholds()`
    из `HouseholdContext` (`households`, `status`, `refetch`).
  - Формы: react-hook-form + zod (`src/lib/validation-schemas.ts`), `Form` из `components/ui/form`;
    `Select`, `Dialog`, `Button`, `Input`, `toast` есть в `components/ui`.
  - Ошибки API — `ApiError` (`src/auth/apiError`), паттерн обработки — `HouseholdEditor`.
  - i18n — неймспейсы в `src/i18n/locales/en/*.json`.

## Дизайн

### Маршрут и вход

- `App.tsx`: `<Route path="/households/:id/limits" element={guard(<CategoryLimitsPage />)} />`,
  страница лениво загружается, как остальные.
- `HouseholdCard`: кнопка «Лимиты» (`variant="outline" size="sm"`, aria-label «Лимиты бюджета
  <имя>»), `Link` на `/households/:id/limits`.
- Шапка страницы: ссылка «← Бюджеты» на `/households`, заголовок `<имя бюджета> · Лимиты`,
  строка «Валюта бюджета: EUR».
- Бюджет берётся из `useHouseholds().households` по `:id`. Пока список грузится — `LoadingFallback`;
  нет такого id — «Бюджет не найден» + ссылка на список.

### Данные

- `src/api/categoryLimits.ts`: `list(hid)`, `create(hid, body)`, `update(hid, categoryId, body)`,
  `remove(hid, categoryId)`; эндпоинты — в `src/const/categoryLimits.ts` через `householdPath`.
- `src/types/categoryLimits.ts`: `LimitPeriodType`, `CategoryLimit`, тела запросов.
- `src/hooks/useCategoryLimits.ts`:
  - запрос `['households', hid, 'category-limits']`;
  - категории — тот же ключ `['households', hid, 'categories']`, что у `useCategoryTree`, но с `hid`
    из параметра, а не активного (для этого — маленький `useCategories(hid)` или параметр);
  - мутации `save` (POST или PUT, см. ниже) и `remove`. `onSuccess`: заменить запись категории в кэше
    лимитов ответом сервера (`setQueryData`) и инвалидировать `['households', hid, 'category-limits']`
    с `refetchType: 'none'` для отчёта HAN-29 (ключ отчёта начинается с того же префикса).
- **POST или PUT:** открытый лимит есть (`effective_to === null`) → `PUT`; нет лимита или он
  доживающий → `POST`.
- `src/lib/limitPeriods.ts`: `limitPeriodStart(type, isoDate)`, `limitPeriodEnd(type, isoDate)`,
  `todayUtcIsoDate()` — зеркало серверных функций, **UTC** (иначе в первые часы месяца у
  пользователя восточнее UTC подсказка разойдётся с сервером).

### Строки списка

`buildLimitRows(categories, limits)` — чистая функция:

- Строка на каждую категорию из `categories` + её лимит из `limits` (по `category_id`), если есть.
- Лимиты, чьей категории нет в `categories` (`category_archived: true`), — строки «архив» внизу.
- Порядок: с лимитом → без лимита → архивные; внутри — по имени (`localeCompare`).

Состояния строки (`LimitRow`):

| Состояние | Показ | Действия |
|---|---|---|
| без лимита | `Транспорт — без лимита` | [+ Задать] |
| действует | `Еда — 400 € / месяц` | [✎] [✕] |
| доживает (`effective_to` не null) | `Еда — 400 € / месяц · до 1 декабря` | [+ Задать] (→ `POST`) |
| старая валюта (`currency ≠ household.currency`) | `400 USD / месяц`, подсказка «при изменении — в EUR» | как «действует» |
| архив | приглушённо, `Архив` | нет (сервер ответит 404) |
| правка | инлайн-форма (ниже) | [Сохранить] [Отмена] |

- Одновременно в правке одна строка; открыть другую — текущая закрывается без сохранения.
- Иконочные кнопки с aria-label («Изменить лимит Еда», «Снять лимит Еда»).
- Суммы — существующим форматтером денег с валютой (`src/lib/format.ts`).

### Инлайн-форма

- Поля: сумма (`Input inputMode="decimal"`) и период (`Select`: Месяц / Квартал / Полгода / Год);
  валюта бюджета — текстом рядом с суммой.
- Значения по умолчанию: текущий лимит; для новой — пустая сумма, «Месяц».
- zod-схема `categoryLimitSchema` в `validation-schemas.ts`: сумма — число `> 0`, `≤ 1e12`, не больше
  2 знаков после запятой (запятая как разделитель принимается); период — одно из 4.
- «Сохранить» неактивна, пока значения не изменились (для существующего открытого лимита).
- Подсказка под формой (`aria-live="polite"`), меняется вместе с периодом:
  - `S = limitPeriodStart(period, today)` → «Действует с ноября 2026. Прошлые периоды не меняются.»
    (для квартала — «с IV квартала 2026», полугодия — «со II полугодия 2026», года — «с 2026 года»);
  - если меняется тип у действующего лимита и `S` раньше начала текущего периода старого типа —
    добавить: «Октябрь и ноябрь как месяцы останутся без лимита» (перечисление периодов старого
    типа от `S` до текущего включительно; для длинного списка — «с октября по ноябрь»).
- Enter сохраняет, Esc отменяет. После успеха строка возвращается в показ, фокус — на кнопку ✎.

### Снятие лимита

- [✕] → `Dialog`: «Снять лимит „Еда“? Лимит действует до 1 декабря 2026, затем снимется. Остаток
  этого периода не перенесётся дальше.» [Отмена] [Снять].
- Дата — из `limitPeriodEnd(type, today)` до запроса; после ответа строка показывает
  `effective_to` из ответа.

### Ошибки

| Ответ | Что видит пользователь | Что делаем |
|---|---|---|
| 409 (`POST`) | «У категории уже есть лимит — список обновлён» под формой | перечитать лимиты, форма остаётся открытой |
| 404 | «Категория удалена или лимита уже нет — список обновлён» | перечитать категории и лимиты, закрыть форму |
| 400 | текст под полем «сумма» | — |
| 403 / сеть / прочее | toast с общей ошибкой | — |
| ошибка загрузки списка | блок «Не удалось загрузить» + «Повторить» (как на `HouseholdsPage`) | — |

Пустой бюджет без категорий — «В бюджете нет категорий».

### i18n

Новый неймспейс `limits` (`src/i18n/locales/en/limits.json`): заголовок, названия периодов,
подсказки, ошибки, диалог; кнопка «Лимиты» — в `households.json`.

## Подходы (рассмотрены)

1. **React Query, ответ сервера — в кэш, подсказка считается на клиенте** — *выбран*. Как устроен
   проект; подсказка доступна до сохранения, как требует тикет.
2. Показывать дату только после сохранения, из ответа — не выполняет критерий «видно при изменении».
3. Оптимистичные обновления — сервер переписывает соседние версии, честнее показать его ответ.

## Тесты

Vitest + RTL, API замокан, как в существующих тестах страниц.

- `limitPeriods`: начало/конец всех 4 типов, 31-е, февраль, декабрь → январь, UTC около полуночи.
- `buildLimitRows`: сортировка, доживающий, архивный, старая валюта.
- Схема: `0`, отрицательное, 3 знака, `> 1e12`, запятая.
- Форма: подсказка меняется с периодом; предупреждение при месяц → квартал; неактивная
  «Сохранить» без изменений; POST для новой/доживающей, PUT для открытой.
- Снятие: диалог с датой, после — «до …».
- Ошибки 409 и 404 — текст и перезапрос.
- Страница: неизвестный `:id` → «Бюджет не найден»; `HouseholdCard` — кнопка «Лимиты» ведёт на маршрут.
